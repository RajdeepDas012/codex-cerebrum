**Topic:** Node.js event loop — understanding non-blocking I/O  
**Category:** `language-specific`  
**Difficulty:** `advanced`  
**Language:** `javascript`  

### Summary
The Node.js event loop is a mechanism that allows Node.js to perform non-blocking I/O operations despite JavaScript being single-threaded, by offloading operations to the system kernel whenever possible. Understanding its phases (Timers, Pending Callbacks, Poll, Check, Close) is critical for diagnosing performance bottlenecks and managing asynchronous flow.

### Key Points
- Node.js runs JavaScript on a single main thread, using libuv under the hood to handle asynchronous system operations via a thread pool and kernel polling.
- The event loop operates in distinct phases: Timers (setTimeout/setInterval), Poll (retrieving I/O events), Check (setImmediate), and Close callbacks.
- Microtasks (process.nextTick and Promise.then callbacks) execute immediately after the current operation completes, before the event loop advances to the next phase.
- Heavy CPU-bound synchronous tasks block the main thread, freezing the event loop and delaying all pending asynchronous callbacks and timers.

### Code Example
*Demonstrates execution order between process.nextTick, promises, timers, and setImmediate*

```javascript
console.log('1: Start');

setTimeout(() => console.log('4: Timer'), 0);
setImmediate(() => console.log('5: Immediate'));

Promise.resolve().then(() => console.log('3: Promise'));
process.nextTick(() => console.log('2: NextTick'));

console.log('6: End');
```

**❌ Common mistake:**
```javascript
// BAD: Assuming setTimeout(..., 0) always executes before setImmediate regardless of context
setTimeout(() => console.log('Timer'), 0);
setImmediate(() => console.log('Immediate'));
// Inside an I/O cycle callback, setImmediate is guaranteed to run before setTimeout(..., 0).
```

### Best Practices
- ✅ Offload heavy CPU-bound computations to worker threads (Worker Threads API) or external microservices.
- ✅ Prefer asynchronous APIs (fs.promises, streams) over synchronous alternatives (fs.readFileSync) to keep the event loop responsive.
- ✅ Use setImmediate instead of setTimeout(fn, 0) when you need code to run immediately after the current poll phase I/O cycle.

### Interview Questions
**Q:** What is the difference in execution order between process.nextTick() and Promise.resolve().then()?  
**A:** Both are microtasks, but process.nextTick() has its own queue that is always processed completely before the standard Promise microtask queue during the transition between operations.  

**Q:** Why does setImmediate sometimes run before setTimeout(..., 0) and sometimes after?  
**A:** If called from the main module, the order is non-deterministic depending on performance. However, if called inside an I/O cycle callback, setImmediate is reliably guaranteed to execute before setTimeout.

**Category:** `databases`  
**Difficulty:** `intermediate`  
**Language:** `language-agnostic`  

### Summary
Database indexes are special lookup structures, typically B-Trees, that improve the speed of data retrieval operations on a table at the cost of additional writes and storage space. Proper indexing transforms slow O(N) full table scans into fast O(log N) operations for frequently queried columns.

### Key Points
- B-Trees are the most common index structure, keeping data sorted for efficient range queries and equality lookups.
- Indexes speed up SELECT queries, JOIN operations, and WHERE clause filters significantly.
- Every index adds overhead to INSERT, UPDATE, and DELETE operations because the index must also be modified.
- Composite indexes rely on leftmost prefix matching, meaning the order of columns in the index definition matters.

### Code Example
*Demonstrates creating a targeted composite index matching common query filters versus over-indexing columns.*

```sql
-- GOOD: Creating a composite index for columns frequently queried together

```

**❌ Common mistake:**
```sql
-- BAD: Creating individual indexes on every single column without considering query patterns

CREATE INDEX idx_status ON orders (status);
CREATE INDEX idx_date ON orders (created_at);
```

### Best Practices
- ✅ Analyze slow query logs and use EXPLAIN or EXPLAIN ANALYZE before adding indexes.
- ✅ Keep composite index column order aligned with filtering selectivity and equality checks first, then range queries.
- ✅ Regularly audit and drop unused or redundant indexes to optimize write operations.

### Interview Questions
**Q:** How does a B-Tree index work and why is it preferred over a hash index for general queries?  
**A:** A B-Tree organizes data in a self-balancing tree structure that maintains sorted order, enabling efficient equality lookups as well as range queries (e.g., BETWEEN, >, <). Hash indexes only support O(1) exact match lookups and cannot handle range operations.  

**Q:** What is the leftmost prefix rule in composite indexes?  
**A:** For a composite index on columns (A, B, C), the database can use the index for queries filtering on A, (A, B), or (A, B, C). However, it cannot efficiently use the index if the query only filters on B or C without including A.

**Topic:** WebSockets vs HTTP polling — real-time data strategies  
**Category:** `system-design`  
**Difficulty:** `intermediate`  
**Language:** `language-agnostic`  

### Summary
Choosing the correct transport mechanism for real-time applications requires balancing latency, server load, and architectural complexity. HTTP polling repeatedly requests data at intervals, whereas WebSockets maintain a persistent, full-duplex TCP connection for instant bidirectional communication.

### Key Points
- HTTP polling creates a new request-response cycle on every check, generating massive HTTP header overhead and unnecessary server load if data hasn't changed.
- Short polling asks for data at fixed intervals; long polling holds the HTTP connection open until new data arrives or a timeout occurs.
- WebSockets perform a single HTTP handshake, then upgrade the connection to a persistent TCP socket allowing asynchronous message pushing from client or server.
- WebSockets require explicit state management, heartbeat mechanisms (ping/pong) to detect dead connections, and horizontal scaling strategies like Redis pub/sub.

### Code Example
*Demonstrates setting up a resilient WebSocket client with automatic reconnection logic.*

```javascript
function connectWebSocket(url) {
  const ws = new WebSocket(url);
  ws.onopen = () => console.log('Connected');
  ws.onmessage = (event) => console.log('Received:', event.data);
  ws.onclose = () => {
    console.log('Disconnected. Reconnecting in 3s...');
    setTimeout(() => connectWebSocket(url), 3000);
  };
  ws.onerror = (error) => ws.close();
}
```

**❌ Common mistake:**
```javascript
// BAD: Assuming the connection stays alive forever without handling drops or reconnection
const ws = new WebSocket('wss://api.example.com');
ws.onmessage = (event) => updateUI(event.data);
ws.send('Hello'); // Fails immediately if connection isn't open yet
```

### Best Practices
- ✅ Use Server-Sent Events (SSE) instead of WebSockets if data flow is strictly server-to-client and automatic reconnection built into the browser is desired.
- ✅ Implement exponential backoff with jitter for WebSocket reconnection attempts to prevent thundering herd problems after a server outage.
- ✅ Offload WebSocket session state to a distributed broker like Redis when scaling across multiple server instances.

### Interview Questions
**Q:** How do you scale WebSockets horizontally across multiple backend servers?  
**A:** By using a message broker like Redis Pub/Sub or Apache Kafka so that when a message needs to be sent to a specific user, the server currently holding that user's WebSocket connection receives the event via the broker.  

**Q:** What is the difference between HTTP long polling and WebSockets?  
**A:** Long polling closes the HTTP connection after every response and opens a new one, sending full HTTP headers each time. WebSockets keep a single TCP connection open permanently, drastically reducing overhead for frequent messages.

### Summary
Context managers allow you to allocate and release resources precisely when needed using the with statement. By implementing either class-based dunder methods (__enter__ and __exit__) or generator-based functions with the @contextmanager decorator, developers can ensure safe resource management such as file handling or database connections.

### Key Points
- The with statement relies on the context management protocol, which consists of the __enter__ and __exit__ methods.
- The __enter__ method executes before the code block inside the with statement runs and its return value is bound to the as target variable.
- The __exit__(exc_type, exc_val, exc_tb) method executes after the block finishes, even if exceptions occur, handling cleanup and exception suppression.
- The contextlib module provides the @contextmanager decorator, allowing you to turn a simple generator function into a context manager using yield.

### Code Example
*Demonstrates writing a custom context manager using the contextlib generator approach.*

```python
from contextlib import contextmanager

@contextmanager
def managed_resource(name):
    print(f"Acquiring {name}")
    try:
        yield name
    finally:
        print(f"Releasing {name}")

with managed_resource("database connection") as res:
    print(f"Using {res}")
```

**❌ Common mistake:**
```python
# BAD: Manual try-finally blocks scattered everywhere leading to resource leaks
res = open_connection()
try:
    use(res)
finally:
    res.close()
```

### Best Practices
- ✅ Use the contextlib.contextmanager decorator for simpler stateful functions to reduce boilerplate compared to writing classes.
- ✅ Always place resource release logic inside a finally block or the __exit__ method to guarantee execution.
- ✅ Keep context managers focused on a single resource or setup/teardown concern to maintain high cohesion.

### Interview Questions
**Q:** How do you write a custom context manager in Python?  
**A:** You can either implement a class with __enter__ and __exit__ methods, or write a generator function decorated with @contextlib.contextmanager where setup happens before yield and teardown happens inside a finally block.  

**Q:** How can you suppress an exception inside a custom context manager's __exit__ method?  
**A:** By having the __exit__ method return a true value (like True). If it returns None or False, any exception raised inside the with block will propagate normally.

**Topic:** Memoization and caching — reducing redundant computation  
**Category:** `algorithms`  
**Difficulty:** `intermediate`  
**Language:** `language-agnostic`  

### Summary
Memoization is an optimization technique that stores the results of expensive function calls and returns the cached result when the same inputs occur again. It trades memory space for execution speed, transforming exponential-time algorithms into linear-time ones.

### Key Points
- Memoization is a specific form of caching focused exclusively on pure function return values based on input arguments.
- It relies on the principle of referential transparency, meaning a function must always return the exact same output for the same input without side effects.
- Cache lookup overhead (e.g., hash map access) must be significantly lower than the cost of the recomputation for the optimization to be effective.
- Unbounded caches can lead to severe memory leaks, necessitating eviction policies like LRU (Least Recently Used) in production environments.

### Code Example
*Demonstrates manual memoization using a decorator versus a non-memoized recursive function.*

```python
def memoize(func):
    cache = {}
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
        return cache[args]
    return wrapper

@memoize
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

**❌ Common mistake:**
```python
def fibonacci(n):
    # BAD: Recomputes overlapping subproblems exponentially
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

### Best Practices
- ✅ Use built-in utility wrappers like functools.lru_cache in Python or Lodash memoize in JavaScript rather than writing custom cache logic from scratch.
- ✅ Ensure cache keys are hashable and represent the complete set of parameters influencing the function output.
- ✅ Monitor cache hit-to-miss ratios to validate whether the memoization strategy is providing a meaningful performance boost.

### Interview Questions
**Q:** What is the difference between memoization and standard caching?  
**A:** Memoization is specifically an algorithmic optimization technique that automatically caches the return values of pure functions based on their parameters, whereas caching is a broader term encompassing any temporary data storage strategy (like database query results or HTTP responses).  

**Q:** How would you handle memoizing a function that accepts an object or array as an argument in JavaScript?  
**A:** Since objects and arrays are reference types in JavaScript, passing a new object instance with identical properties creates a cache miss. You must serialize the arguments into a string (e.g., JSON.stringify) or extract primitive values to use as a reliable cache key.

Unit testing patterns combine fixtures for setup/teardown isolation, mocks for replacing external dependencies with controlled behavior, and assertions for verifying expected outcomes. Mastering these patterns ensures tests are fast, reliable, and focused solely on the unit under test.

```python

from unittest.mock import Mock

@pytest.fixture

def test_get_username(mock_db):
    # Arrange
    service = UserService(mock_db)
    # Act

    # Assert
```

**Topic:** Blockchain consensus mechanisms — PoW vs PoS vs DPoS explained  
**Category:** `system-design`  
**Difficulty:** `advanced`  
**Language:** `language-agnostic`  

### Summary
Consensus mechanisms are algorithmic protocols that allow distributed nodes to agree on a single source of truth and state of a blockchain network. Proof of Work (PoW), Proof of Stake (PoS), and Delegated Proof of Stake (DPoS) represent different trade-offs between decentralization, security, and scalability.

### Key Points
- Proof of Work (PoW) relies on computational power (hash rate) and electricity, offering high security but low throughput and extreme energy consumption.
- Proof of Stake (PoS) replaces miners with validators who lock up (stake) native tokens, drastically reducing energy usage while maintaining cryptographic finality.
- Delegated Proof of Stake (DPoS) introduces a representative democracy model where token holders vote for a small, fixed set of block producers, maximizing transaction speed at the cost of higher centralization.
- The Blockchain Trilemma dictates that a decentralized system can only effectively achieve two of the three properties simultaneously: decentralization, security, and scalability.

### Code Example
*Demonstrates a simplistic validator selection process in a Proof of Stake system based on stake-weighted probability.*

```python
# GOOD: Weighting validator selection proportionally to their locked stake
import random

def select_validator(validators):
    # validators is a dict: {address: stake_amount}
    total_stake = sum(validators.values())
    pick = random.uniform(0, total_stake)
    current = 0
    for address, stake in validators.items():
        current += stake
        if current >= pick:
            return address
    return list(validators.keys())[0]
```

**❌ Common mistake:**
```python

```

### Best Practices
- ✅ Implement slashing conditions in PoS and DPoS networks to cryptographically penalize double-signing and malicious offline behavior.
- ✅ Design DPoS architectures with dynamic rotation and reputation metrics for delegates to prevent cartel formation among top block producers.
- ✅ Balance block size and block time parameters carefully to prevent network propagation delays that can cause chain splits.

### Interview Questions
**Q:** What is a Nothing-at-Stake attack in Proof of Stake, and how do protocols mitigate it?  
**A:** A Nothing-at-Stake attack occurs when validators vote on multiple conflicting forks simultaneously because doing so costs them nothing and maximizes potential rewards. ### Code Example
*Calculate standard 14-period Relative Strength Index using pandas*

```python
import pandas as pd

def calculate_rsi(prices, period=14):
    delta = prices.diff()
    gain = delta.clip(lower=0)
    loss = -1 * delta.clip(upper=0)
    avg_gain = gain.ewm(com=period - 1, min_periods=period).mean()
    avg_loss = loss.ewm(com=period - 1, min_periods=period).mean()
    rs = avg_gain / avg_loss
    return 100 - (100 / (1 + rs))
```

### Code Example
*Calculates Bollinger Bands and detects squeeze conditions using pandas*

```python
import pandas as pd

def calculate_bollinger_bands(df, window=20, num_std=2):
    df['SMA'] = df['Close'].rolling(window=window).mean()
    df['STD'] = df['Close'].rolling(window=window).std()
    df['Upper'] = df['SMA'] + (df['STD'] * num_std)
    df['Lower'] = df['SMA'] - (df['STD'] * num_std)
    df['Bandwidth'] = (df['Upper'] - df['Lower']) / df['SMA']
    df['Squeeze'] = df['Bandwidth'] < df['Bandwidth'].rolling(120).quantile(0.1)
    return df
```

### Code Example
*Calculates option delta and portfolio exposure accurately using Black-Scholes formulas.*

```python
import math
from scipy.stats import norm

def calculate_call_delta(S, K, T, r, sigma):
    if T <= 0:
        return 1.0 if S > K else 0.0
    d1 = (math.log(S / K) + (r + 0.5 * sigma ** 2) * T) / (sigma * math.sqrt(T))
    return norm.cdf(d1)
```

### Summary
Dollar cost averaging (DCA) is an investment strategy where an investor divides up the total amount to be invested across periodic purchases of a target asset in an effort to reduce the impact of volatility. By investing a fixed dollar amount regularly regardless of the asset's price, the strategy automatically purchases more shares when prices are low and fewer shares when prices are high.

### Key Points
- DCA mathematically results in a lower average cost per share than the average price paid over time during a declining or volatile market, a phenomenon known as share averaging.
- The primary psychological benefit is removing emotion and market-timing anxiety from the investment process through automation.
- Backtest results across historical equity indexes (like the S&P 500) show that lump-sum investing generally outperforms DCA roughly two-thirds of the time due to upward market drift, but DCA provides superior risk mitigation for lump sums deployed near market peaks.
- The mathematical mechanics dictate that total shares accumulated equal the sum of (Fixed Investment Amount / Current Price) across all intervals.

### Code Example
*Simulate and calculate the final portfolio value and average cost per share using a DCA strategy.*

```python
def simulate_dca(prices, periodic_amount):
    total_shares = 0.0
    total_invested = 0.0
    for price in prices:
        shares = periodic_amount / price
        total_shares += shares
        total_invested += periodic_amount
    avg_cost = total_invested / total_shares
    final_value = total_shares * prices[-1]
    return {'total_invested': total_invested, 'final_value': final_value, 'avg_cost': avg_cost}
```

**❌ Common mistake:**
```python

    # BAD: Averaging prices directly instead of share counts
    avg_price = sum(prices) / len(prices)
    total_shares = (len(prices) * periodic_amount) / avg_price
    return total_shares
```

### Best Practices
- ✅ Automate recurring purchases through a brokerage API or bank transfer to ensure strict adherence without emotional interference.
- ✅ Use DCA specifically for cash flows derived from ongoing income (e.g., monthly savings) rather than holding a massive lump sum out of the market indefinitely.
- ✅ Maintain a long-term investment horizon (at least 3 to 5 years) to smooth out short-term macroeconomic volatility.

### Interview Questions
**Q:** Mathematically, why does DCA result in a lower average cost per share than the arithmetic mean of asset prices over the investment period?  
**A:** Because a fixed dollar amount buys inversely proportional quantities of shares relative to the price; you mathematically purchase a higher volume of shares when prices are depressed and fewer shares when prices are inflated (harmonic mean vs. arithmetic mean).  

**Q:** How does DCA compare to lump-sum investing in backtests, and why does one typically outperform?  
**A:** Lump-sum investing outperforms DCA roughly 60-70% of the time in historical backtests because markets spend more time rising than falling (upward drift), meaning putting money to work immediately exposes capital to equity growth sooner.

- Senkou Span A and B (Cloud / Kumo): Span A (average of Tenkan and Kijun plotted 26 periods ahead) and Span B (50-period high/low average plotted 26 periods ahead) form the cloud, projecting future support and resistance zones.

### Code Example

### Summary
Market microstructure studies the mechanics of how orders are executed, matched, and cleared within financial exchanges. Understanding limit order books, priority rules, and liquidity dynamics is crucial for minimizing execution costs like slippage in high-throughput trading systems.

### Key Points
- The Limit Order Book (LOB) maintains open buy (bids) and sell (asks) orders ordered by price-time priority.
- Order matching engines use FIFO (First In, First Out) or pro-rata algorithms to allocate fills among competing orders at the same price level.
- Slippage occurs when the expected execution price differs from the actual fill price due to insufficient liquidity or latency delay.
- Market orders consume existing liquidity (crossing the spread), whereas limit orders add liquidity and earn rebates.

### Code Example
*Simulates a matching engine processing limit orders and calculating potential slippage.*

```python
class MatchingEngine:
    def __init__(self):
        self.bids = []  # max-heap simulation
        self.asks = []  # min-heap simulation

    def execute_market_order(self, side, quantity):
        filled_qty = 0
        total_cost = 0.0
        book = self.asks if side == 'BUY' else self.bids
        
        while quantity > 0 and book:
            best_price, available_qty = book[0]
            match_qty = min(quantity, available_qty)
            total_cost += match_qty * best_price
            filled_qty += match_qty
            quantity -= match_qty
            if match_qty == available_qty:
                book.pop(0)
            else:
                book[0] = (best_price, available_qty - match_qty)
                
        return total_cost / filled_qty if filled_qty > 0 else None
```


- ✅ Use iceberg orders or TWAP/VWAP execution algorithms to break large orders into smaller chunks and reduce market impact.
- ✅ Monitor order book depth and historical volatility to dynamically adjust maximum acceptable slippage tolerances.
- ✅ Design asynchronous ingestion pipelines to minimize internal processing latency before hitting the exchange gateway.

### Interview Questions

**A:** Price-time priority dictates that orders with the best price are matched first. If multiple orders share the same price, the order submitted earliest in time is matched first (FIFO).

### Summary
A mean reversion strategy is a trading approach based on the premise that asset prices and historical returns eventually return to their long-term average or mean. When a price deviates significantly from its moving average, traders take a contrarian position, betting that the price will correct back toward the baseline.

### Key Points
- Operates on the 'rubber band' theory where extreme price movements are temporary distortions.
- Relies heavily on statistical measures like moving averages, standard deviation, and the Z-score.
- Frequently uses technical oscillators like the Relative Strength Index (RSI) or Bollinger Bands to spot overbought and oversold conditions.
- Performs best in range-bound markets with low structural volatility.

### Code Example
*Calculates a simple moving average and standard deviation bands to generate a Z-score signal for mean reversion.*

```python
import numpy as np
import pandas as pd

def calculate_z_score(prices, window=20):
    sma = prices.rolling(window=window).mean()
    std = prices.rolling(window=window).std()
    z_score = (prices - sma) / std
    return z_score

# Generate signals: sell when Z > 2, buy when Z < -2
prices = pd.Series([100, 102, 101, 103, 115])
z = calculate_z_score(prices, window=3)
```

### Best Practices

- ✅ Combine price Z-scores with volume or liquidity checks to confirm that the price spike was driven by noise rather than structural demand.
- ✅ Backtest your strategy across multiple market regimes to ensure it doesn't just overfit to a single sideways-trading year.

### Interview Questions

**A:** Lagging indicators like moving averages react slowly to rapid price changes, causing late entries and exits, and they fail completely during aggressive trend breakouts.

### Summary
A breakout trading strategy involves entering a position when the asset price moves outside a defined support or resistance level with increased volume. It matters because it captures the beginning of strong, explosive directional trends.

### Key Points
- Identify key consolidation zones, channels, or chart patterns like triangles and rectangles.
- Entry is triggered when the price breaches the resistance or support boundary.
- Stop loss is typically placed just inside the consolidation range or below the breakout candle.
- Profit targets are calculated using the measured move technique, projecting the height of the range upwards from the breakout point.

### Code Example
*Calculates breakout entry, stop loss, and target based on a resistance channel.*

```python
def calculate_breakout(highs, current_price, atr):
    resistance = max(highs[-20:])
    if current_price > resistance:
        entry = current_price
        stop_loss = resistance - (1.5 * atr)
        target = entry + (resistance - min(highs[-20:]))
        return entry, stop_loss, target
    return None
```

**❌ Common mistake:**
```python
def calculate_breakout(highs, current_price):
    resistance = max(highs[-20:])
    entry = current_price
    stop_loss = resistance - 1.0
    target = entry + 10.0

```

### Best Practices
- ✅ Always confirm breakouts with above-average volume.
- ✅ Use Average True Range (ATR) to adjust stop losses dynamically based on current market volatility.
- ✅ Wait for a retest of the broken level before executing the entry to filter out fakeouts.

### Interview Questions
**Q:** How do you mitigate the risk of false breakouts in an algorithmic trading system?  
**A:** By requiring confirmation metrics such as volume spikes exceeding a moving average threshold and waiting for the candle close outside the resistance level rather than trading intraday wicks.  

**Q:** What is the 'measured move' method for calculating price targets in a breakout strategy?  
**A:** It involves taking the vertical height of the preceding consolidation range (the distance between support and resistance) and projecting that exact distance outward from the breakout point.

### Key Points

- Demands strict risk-to-reward ratios where stop losses are often tighter than profit targets, yet absolute win rates must remain high.
- Transaction costs (commissions and slippage) play a massive role and can easily turn a profitable strategy into a losing one.

### Code Example
*Calculates net profit of a scalp trade factoring in exchange commissions per round-trip*

```python
def calculate_scalp_net_pnl(entry_price, exit_price, position_size, fee_rate):
    gross_pnl = (exit_price - entry_price) * position_size
    total_fees = (entry_price + exit_price) * position_size * fee_rate
    return gross_pnl - total_fees
```

**Category:** `trading-strategies`  
**Difficulty:** `intermediate`

### Summary
Swing trading is a style that aims to capture short- to medium-term gains in a stock or other asset over a period of several days to several weeks. By utilizing technical analysis, traders identify multi-day price 'swings' to enter positions aligned with the prevailing trend.

### Key Points
- Utilizes daily and 4-hour charts to spot medium-term trend reversals or continuations.
- Balances reward and risk by aiming for larger percentage moves than scalping while avoiding long-term capital lockup.
- Relies heavily on support and resistance levels, moving averages, and oscillators like the RSI or MACD.
- Requires overnight risk management since positions remain open while markets are closed.

### Code Example
*Identifies swing high and swing low points using a rolling window over daily closing prices.*

```python
import pandas as pd

def identify_swings(df, window=5):
    df['swing_high'] = df['high'][(df['high'] == df['high'].rolling(window*2+1, center=True).max())]
    df['swing_low'] = df['low'][(df['low'] == df['low'].rolling(window*2+1, center=True).min())]
    return df.dropna(subset=['swing_high', 'swing_low'], how='all')
```

**❌ Common mistake:**
```python

def identify_swings(df):
    # Mistake: Using past data only without center window, causing lagging swing points

    return df
```

### Best Practices
- ✅ Align swing trades with the broader weekly or monthly market trend to increase probability of success.
- ✅ Scale out of positions partially at predefined profit targets to lock in gains while letting a runner ride.
- ✅ Calculate position size based on the distance to your daily chart stop-loss level, risking no more than 1-2% of total capital.

### Interview Questions
**Q:** How do you manage overnight gap risk in a swing trading portfolio?  
**A:** By reducing position sizes before major catalyst events (like FOMC meetings or earnings), diversifying across non-correlated sectors, and utilizing options hedges when necessary.  

**Q:** What is the primary difference between swing trading and position trading?  
**A:** Swing trading typically focuses on holdings lasting from a few days to several weeks based on technical patterns, whereas position trading lasts for months or years and heavily incorporates fundamental analysis.
