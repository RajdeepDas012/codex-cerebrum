### Interview Questions
**Q:** How do you implement a lock-free set operation on a shared bit array without using heavy mutex locks?  
**A:** By using atomic bitwise instructions or compare-and-swap (CAS) loops that repeatedly attempt to apply a bitwise OR mask until the hardware confirms the update succeeded without interference.  

**Q:** What is the primary challenge when dynamically resizing a concurrent Bloom filter, and how does epoch-based memory reclamation solve it?  
**A:** The challenge is safely freeing or replacing the old bit array while other threads are actively querying it. Epoch-based reclamation delays the destruction of the old memory block until all active reader threads have safely exited the current processing epoch.

### Interview Questions
**Q:** How do the three metadata bits (is_occupied, run_continuation, shifted) work together to reconstruct clusters in a quotient filter without storing explicit keys?  
**A:** is_occupied indicates a fingerprint's canonical slot has a corresponding remainder in the table; run_continuation marks slots that belong to a run rather than starting a new one; shifted indicates whether a slot has been displaced from its canonical home position due to a collision.  

**Q:** Why is epoch-based memory reclamation preferred over reference counting when implementing concurrent dynamic resizing for lock-free filters?  
**A:** Epoch-based reclamation avoids the high atomic read/write overhead of updating reference counts on every single query probe, only incrementing thread epoch counters upon entering critical sections.
