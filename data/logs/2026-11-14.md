```cpp
template<typename T, size_t Capacity>
class MPSCQueue {
    struct Node { std::atomic<size_t> sequence; T data; };
    std::array<Node, Capacity> buffer_;
    std::atomic<size_t> head_{0};
    std::atomic<size_t> tail_{0};
public:
    bool enqueue(const T& item) {
        size_t pos = tail_.load(std::memory_order_relaxed);
        for (;;) {
            Node& node = buffer_[pos % Capacity];
            size_t seq = node.sequence.load(std::memory_order_acquire);
            intptr_t dif = (intptr_t)seq - (intptr_t)pos;
            if (dif == 0) {
                if (tail_.compare_exchange_weak(pos, pos + 1, std::memory_order_relaxed))
                    break;
            } else if (dif < 0) {
                return false;
            } else {
                pos = tail_.load(std::memory_order_relaxed);
            }
        }
        return true;
    }
};
```

### Key Points
- Leverages memory ordering semantics (acquire-release) to eliminate full memory barriers on sequentially consistent platforms.
- Completely avoids locks, preventing priority inversion, context switching overhead, and thread contention.
- Maintains distinct cache lines for head and tail pointers to prevent false sharing in multi-core processors.
- Uses power-of-two buffer sizing to optimize modulo operations into efficient bitwise masking.

### Code Example
*Demonstrates thread-safe atomic pointer loading and storing with acquire-release semantics in an SPSC queue.*

```cpp
template <typename T, size_t Capacity>
class SPSCQueue {
    alignas(64) std::atomic<size_t> head_{0};
    alignas(64) std::atomic<size_t> tail_{0};
    T buffer_[Capacity];
public:
    bool push(const T& item) {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t tail = tail_.load(std::memory_order_acquire);
        if ((tail - head) == Capacity) return false;
        buffer_[tail % Capacity] = item;
        tail_.store(tail + 1, std::memory_order_release);
        return true;
    }
};
```

**❌ Common mistake:**

```cpp
template <typename T, size_t Capacity>
class BadQueue {

    }
};
```

### Best Practices
- ✅ Pad atomic head and tail pointers using `alignas(hardware_destructive_interference_size)` to prevent cache bouncing.
- ✅ Use `std::memory_order_relaxed` for operations where synchronization is not required, combined with acquire-release for inter-thread visibility.
- ✅ Ensure buffer capacity is a power of two to substitute expensive modulo operators with fast bitwise AND masks.

### Interview Questions
**Q:** Why is an SPSC queue significantly faster and simpler to implement than an MPMC queue?  
**A:** Because there is only one writer and one reader, head and tail pointers can be loaded and stored atomically without needing CAS (Compare-And-Swap) retry loops, avoiding race conditions on pointer updates.  

**Q:** What is the role of memory order acquire and release in an SPSC ring buffer?  
**A:** Store-release ensures that prior writes to the ring buffer data array are visible before the tail pointer update is published. Load-acquire ensures that reads of the ring buffer data do not execute until the updated pointer load is fully completed.
