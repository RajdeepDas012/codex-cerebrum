```cpp
    alignas(64) std::atomic<size_t> tail_{0};
    T buffer_[Capacity];
public:
    bool push(const T& item) {
        size_t head = head_.load(std::memory_order_relaxed);
        size_t tail = tail_.load(std::memory_order_acquire);

        return true;
    }
};
```


**❌ Common mistake:**
```cpp
Node<T>* search(const Key& key) { Node<T>* curr = head; while (curr && curr->key != key) { curr = curr->next; } return curr; }
```

### Best Practices
- ✅ Always register active threads with the hazard pointer manager before initiating concurrent traversals.
- ✅ Ensure atomic CAS operations on membership vectors enforce sequentially consistent memory ordering to prevent stale routing views.

### Interview Questions
**Q:** How do membership vectors in a Skip Graph differ from traditional random height selection in standard Skip Lists?  
**A:** Skip Graphs use membership vectors derived from node identifiers to determine routing at each level, enabling distributed peer-to-peer search capabilities without relying purely on independent random coin tosses.  

**Q:** Why are hazard pointers necessary when implementing a lock-free Skip Graph?  
**A:** Hazard pointers protect dynamically freed nodes from being reclaimed by the memory allocator while other threads are actively traversing pointers pointing to them, preventing race conditions and segmentation faults.
