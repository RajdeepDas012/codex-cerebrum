### Code Example
*Demonstrates safe atomic updates on a Fenwick tree index using compare-and-swap loops.*


**Q:** Why is epoch-based memory reclamation preferred over reference counting in this concurrent structure?

### Code Example
*Demonstrates thread-safe atomic bit-setting using fetch_or for a concurrent Bloom filter array.*

```cpp
#include <atomic>
#include <vector>

class ConcurrentBloomFilter {
    std::vector<std::atomic<uint64_t>> bit_vector;
    size_t num_bits;
public:
    ConcurrentBloomFilter(size_t size) : num_bits(size), bit_vector((size + 63) / 64) {}
    void insert(size_t hash_val) {
        size_t idx = hash_val % num_bits;
        size_t word_idx = idx / 64;
        uint64_t bit_mask = 1ULL << (idx % 64);
        bit_vector[word_idx].fetch_or(bit_mask, std::memory_order_relaxed);
    }
};
```

```cpp
class UnsafeBloomFilter {
    std::vector<uint64_t> bit_vector;

        bit_vector[hash_val % bit_vector.size()] |= (1ULL << (hash_val % 64));
    }
};
```

### Best Practices

- ✅ Pre-calculate optimal bit array sizes and hash function counts based on expected insertion load factors to minimize false positive rates.

### Interview Questions

**Q:** Why is standard element deletion difficult to implement in a concurrent Bloom filter?

### Key Points

- Employs atomic fetch-add and CAS operations to safely update counters concurrently across threads.

- Guarantees sub-linear space complexity for probabilistic frequency queries in data streams.

### Code Example
*Demonstrates thread-safe concurrent frequency increments using atomic variables in a Count-Min Sketch.*

```cpp
#include <atomic>
#include <vector>

class ConcurrentCountMinSketch {
    std::vector<std::vector<std::atomic<uint64_t>>> table;
    size_t depth, width;
public:
    ConcurrentCountMinSketch(size_t d, size_t w) : depth(d), width(w), table(d, std::vector<std::atomic<uint64_t>>(w)) {}
    
    void increment(const std::string& item) {
        for (size_t i = 0; i < depth; ++i) {
            size_t hash_val = hash(item, i) % width;
            table[i][hash_val].fetch_add(1, std::memory_order_relaxed);
        }
    }
    uint64_t estimate(const std::string& item) const {
        uint64_t min_val = UINT64_MAX;
        for (size_t i = 0; i < depth; ++i) {
            size_t hash_val = hash(item, i) % width;
            min_val = std::min(min_val, table[i][hash_val].load(std::memory_order_relaxed));
        }
        return min_val;
    }
};
```

**❌ Common mistake:**
```cpp
#include <vector>

class UnsafeSketch {
    std::vector<std::vector<uint64_t>> table;
public:
    void increment(const std::string& item) {
        // Race condition: concurrent increments will be lost without atomic operations
        table[0][hash(item) % width]++;
    }
};
```

### Best Practices
- ✅ Use relaxed memory orderings for counter increments since exact atomicity across rows is not required for probabilistic structures.
- ✅ Tune the depth and width parameters based on acceptable error bounds and memory constraints.
- ✅ Combine with a heavy-hitter tracking min-heap structure wrapped in lock-free guards for real-time top-k monitoring.

### Interview Questions
**Q:** Why does the Count-Min Sketch overestimate frequencies rather than underestimate them?  
**A:** Because it relies on multiple hash functions mapping distinct items to the same counters, adding collision noise that only ever increments the counter values.  

**Q:** How do atomic fetch-add primitives improve performance over mutexes in a multi-core Count-Min Sketch?  
**A:** They execute directly at the hardware bus level using cache-coherent instructions without putting threads to sleep, eliminating context-switching overhead and lock contention.

### Code Example
*Demonstrates atomic maximum updates on a shared HyperLogLog register array using CAS loops.*

```cpp
bool update_register(std::atomic<uint8_t>* registers, size_t index, uint8_t val) {
    uint8_t current = registers[index].load(std::memory_order_relaxed);
    while (val > current) {
        if (registers[index].compare_exchange_weak(current, val, std::memory_order_release, std::memory_order_relaxed)) {
            return true;
        }
    }
    return false;
}
```

### Interview Questions
**Q:** How do you handle concurrent updates to the same HyperLogLog register without locking?

**Q:** Why are hazard pointers useful in concurrent probabilistic data structures?  
**A:** They safely manage memory reclamation by ensuring that no thread deletes a memory block while another thread might still be reading or updating it.
