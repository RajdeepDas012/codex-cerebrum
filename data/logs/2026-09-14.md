        self.last_timestamp = -1

        with self.lock:
            if current_time < self.last_timestamp:
                raise Exception("Clock moved backwards.")
            if current_time == self.last_timestamp:
                self.sequence = (self.sequence + 1) & 4095
                if self.sequence == 0:
                    while current_time <= self.last_timestamp:
                        current_time = int(time.time() * 1000)

class DistributedCoordinator:
    def __init__(self, participants):
        self.participants = participants
        self.rollback_log = []

    def execute(self, payload):
        for p in self.participants:
            try:
                res = p.prepare(payload)
                if not res:
                    self.rollback()

**Category:** `data-structures`  
**Difficulty:** `advanced`  
**Language:** `python`  

### Summary
An RCU hash table allows multiple reader threads to traverse and query data concurrently without acquiring locks, achieving near-zero read overhead. Writers perform updates by cloning the modified structure, applying changes, and swapping pointers atomically after active readers finish.

### Key Points
- Readers execute lock-free and wait-free, making read operations extremely fast and predictable in high-concurrency environments.
- Writers isolate modifications by duplicating the target node or bucket array, updating the copy, and publishing the change via an atomic pointer swap.
- Grace periods ensure that old memory structures are not reclaimed until all pre-existing reader critical sections have completed.
- Ideal for read-heavy workloads where configuration data or routing tables are accessed constantly but updated infrequently.

### Code Example
*Demonstrates a thread-safe RCU hash table lookup and copy-on-write update pattern using atomic references and thread local states.*

```python
import threading
import copy

class RCUHashTable:
    def __init__(self):
        self._data = {}
        self._lock = threading.Lock()

    def lookup(self, key):
        # Readers access the current reference lock-free
        current = self._data
        return current.get(key)

    def update(self, key, value):
        with self._lock:
            # Writer copies-on-write, mutates, then swaps pointer atomically
            new_data = dict(self._data)
            new_data[key] = value
            self._data = new_data
```

### Best Practices
- ✅ Keep reader critical sections as short and lightweight as possible to minimize grace period latency for memory reclamation.
- ✅ Use atomic operations or memory barriers to ensure safe pointer visibility across multi-core processor caches.
- ✅ Batch write operations when possible to amortize the overhead of copying data structures and managing grace periods.

### Interview Questions
**Q:** How does RCU eliminate read locks and what is the role of a grace period?  
**A:** RCU allows readers to access shared data without locks by ensuring they read a consistent snapshot. The grace period is the interval required for all pre-existing readers to finish their critical sections, ensuring old memory can safely be reclaimed after a write.  

**Q:** What are the trade-offs of using an RCU hash table compared to a standard read-write lock hash table?  
**A:** RCU offers significantly lower latency and zero contention for readers since no locks are acquired. However, writers face higher overhead due to copying data structures, and memory management becomes more complex due to deferred reclamation.
