### Summary
This topic covers building a concurrent Binary Indexed Tree (Fenwick Tree) that supports lock-free prefix sum queries and point updates. By combining atomic prefix-sum-updating, node-cascading CAS operations, and hazard pointers, multi-core systems can manipulate cumulative frequencies safely without explicit locking overhead.

### Key Points

### Interview Questions
**Q:** How do you handle cascading updates to parent nodes in a lock-free Fenwick tree without causing deadlocks?  
**A:** By using Compare-And-Swap (CAS) retry loops on individual nodes from the target index up to the root, avoiding global locks entirely.  

**Q:** Why are hazard pointers necessary in a concurrent Fenwick tree implementation?  
**A:** They protect nodes from being reclaimed or freed by other threads while the current thread is traversing or modifying pointers along the tree path.
