#include <vector>

class ConcurrentBloomFilter {
    std::vector<std::atomic<size_t>> words;
public:
    ConcurrentBloomFilter(size_t word_count) : words(word_count) {
        for (auto& w : words) w.store(0, std::memory_order_relaxed);
    }
    void set_bit(size_t bit_index) {
        size_t word_idx = bit_index / 64;
        size_t bit_offset = bit_index % 64;
        size_t mask = 1ULL << bit_offset;
        size_t current = words[word_idx].load(std::memory_order_relaxed);

    }
};

### Interview Questions
**Q:** How do you prevent lost updates when multiple threads attempt to set different bits within the same underlying machine word simultaneously?  
**A:** By using a compare-and-swap (CAS) loop that reads the current word value, computes the bitwise OR with the new bit mask, and repeatedly attempts to update the word atomically until it succeeds.  

**Q:** Why are standard Bloom filters difficult to update concurrently without locks?  
**A:** Because multiple hash functions may map distinct items to bits residing within the same memory word or cache line, resulting in data races during read-modify-write cycles.
