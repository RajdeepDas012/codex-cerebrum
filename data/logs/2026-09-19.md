```cpp
    std::atomic<Node*> root;
public:
    bool updateVersion(Node* oldRoot, Node* newRoot) {
        return root.compare_exchange_strong(oldRoot, newRoot);
    }
};
```

**❌ Common mistake:**
```cpp
Node* update(Node* root, int val) {
    root->val = val; // Mutating nodes in place breaks persistence and thread safety
    return root;
}
```

### Best Practices
- ✅ Ensure all node allocations use a thread-safe memory pool or hazard-pointer-managed epoch registry to minimize allocation latency.
- ✅ Keep path-copying operations granular and stateless to make CAS retry loops short and minimize contention on root version pointers.

### Interview Questions
**Q:** How do you achieve thread safety in a persistent data structure without using global locks?  
**A:** By combining immutable path-copying for updates with atomic root-pointer redirection via Compare-And-Swap (CAS) primitives and hazard pointers for memory reclamation.  

**Q:** Why is in-place mutation forbidden when implementing a persistent segment tree?  
**A:** In-place mutation destroys previous historical versions, violating the core persistence guarantee that all past states remain immutable and accessible.
